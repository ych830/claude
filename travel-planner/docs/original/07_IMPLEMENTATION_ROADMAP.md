# 구현 로드맵

## Phase 0. 문서화 및 설계

### 목표
개발 전에 기능 범위, 데이터 구조, API 흐름, 모듈 경계를 확정합니다.

### 산출물
- 제품 기능 매뉴얼
- 시스템 아키텍처 문서
- DB 설계 초안
- API 프로세스 문서
- 개발 규칙 문서

## Phase 1. 프로젝트 초기 세팅

### 작업
- FastAPI 프로젝트 생성
- 폴더 구조 생성
- 환경변수 설정
- DB 연결
- Alembic 설정
- 공통 응답/예외 구조 작성

### 완료 기준
- `/health` API가 정상 동작한다.
- DB 연결 테스트가 통과한다.

## Phase 2. 사용자/인증 기능

### 작업
- User 모델
- Preference 모델
- 회원가입
- 로그인
- JWT 인증
- 내 정보 조회/수정

### 완료 기준
- 인증된 사용자만 일정 생성 API를 호출할 수 있다.

## Phase 3. 장소/지도 기본 기능

### 작업
- Place 모델
- 장소 검색 API
- Google/Kakao 지도 Client
- Geocoding
- 주변 장소 추천

### 완료 기준
- 장소명 입력 시 좌표를 저장할 수 있다.
- 일정에 등록된 장소들을 지도에 표시할 수 있는 데이터를 반환한다.

## Phase 4. AI 일정 생성 MVP

### 작업
- 사용자 취향 입력 Schema
- AI 프롬프트 설계
- LLM Client
- 일정 생성 Service
- Itinerary/Day/Item 저장

### 완료 기준
- 여행지, 기간, 취향을 입력하면 일정표가 생성된다.

## Phase 5. 일정 수정 기능

### 작업
- 일정 조회
- 일정 항목 추가/삭제
- 순서 변경
- 메모 수정
- 비용 수정

### 완료 기준
- 드래그 앤 드롭 결과를 API로 저장할 수 있다.

## Phase 6. SNS 링크 기반 일정 생성

### 작업
- URL 검증
- 게시물 텍스트 수집
- 장소명 추출
- 지도 API 매칭
- 일정표 변환

### 완료 기준
- 공개 블로그 링크를 입력하면 장소 리스트 또는 일정표가 생성된다.

## Phase 7. 공동 편집

### 작업
- 초대 기능
- 권한 관리
- WebSocket
- 일정 변경 이벤트 Broadcast

### 완료 기준
- 초대된 사용자가 같은 일정을 수정할 수 있다.
- 한 사용자의 수정이 다른 사용자 화면에 반영된다.

## Phase 8. 리뷰/팁/관광지 정보

### 작업
- 리뷰 작성
- 비추/쏘쏘/강추 평가
- 팁 작성
- AI 리뷰 요약
- 관광지 운영시간/가격 표시

### 완료 기준
- 장소 상세 화면에 리뷰, 팁, 운영정보가 표시된다.

## Phase 9. 예산/알람/더치페이

### 작업
- 일정별 예상 비용 계산
- 카테고리별 예산 집계
- 일정 알람
- 단순 더치페이 계산
- 결제 연동 확장 설계

### 완료 기준
- 일정별 총 예상 예산을 볼 수 있다.
- 동행자 기준 1인 부담금을 계산할 수 있다.

## Phase 10. 배포 준비

### 작업
- Dockerfile
- docker-compose
- CI/CD
- 운영 환경변수
- 로그/모니터링
- API 문서 정리

### 완료 기준
- 서버 배포 후 Swagger 문서에서 주요 API를 테스트할 수 있다.
